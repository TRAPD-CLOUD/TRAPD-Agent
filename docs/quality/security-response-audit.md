## Coverage and limits

* Commands and config use typed canonical JSON. They must structurally decode before verifying the existing signature. The signature and agent binding precede policy application. IoC updates are signed commands, Sigma rules are signed configuration. Maintenance tokens verify raw domain-prefixed bytes before claims parsing and use a dedicated key, purpose, lifetime and persistent nonce. Update directives and release statements use separate pinned keys. Exact-byte pre-decode verification for commands/config would require a versioned backend envelope carrying the signed payload bytes.
* Update verification checks platform, version, signed size and digest again at apply. The existing recovery journal, replacement, health marker and rollback tests exercise interrupted updates using a simulated service.
* Linux quarantine pins directories and uses no-replace restore. Windows has separate vault, service and registry ACL code. Windows process control checks creation time and image. Isolation and release have dedicated management allowlist and restore paths. Package operations use argument vectors and validate package identifiers. Operator-authorized remote scripts are an explicit exception to shell-free execution.
* The local guard uses peer credentials on its Linux Unix socket and a restricted Windows named pipe. Release CI generates CycloneDX inventories for the agent and eBPF crate. Independent bit-for-bit build reproduction was not tested.
* Maintenance use reporting, Windows uninstall gate and protected service controls provide application-level authorization. Linux root and Windows principals with OS ownership privileges are outside an agent-only guarantee of continued execution. Service-stop reporting and remote liveness are detective controls. Local root can stop both Linux services. Enforcing authorization against such an administrator requires a host policy authority the administrator cannot replace.
* Provisioned tokens come from the protected config directory or the MSI staging key. Existing private agent.env tokens are read directly. Remove launch-environment overrides and pass only a file path to the Windows installer. A previously exported or logged token requires rotation. The agent refuses damaged persisted credentials before enrollment.
* Backend tenant membership and the server's policies for issuing tokens, signing commands and requiring client certificates are outside this repository. File ownership, effective ACL inheritance, service controls, packet routing, and health rollback under actual power loss need host validation.

## Backend changes and recovery

* **SR-07**. Proposed result contract: accept an authenticated result keyed by `(tenant_id, agent_id, command_id)`. Derive the tenant and agent from the authenticated identity and require the persisted target to match. Carry `status: succeeded | failed | interrupted_unknown` and a stable `event_id`. Acknowledge only after durable commit and return the same acknowledgement for a duplicate. Retain unacknowledged results on the endpoint. A durable intent without a terminal result after restart must surface as `interrupted_unknown` for non-transactional actions. Reissuing such actions needs an operator decision. Reserving a live channel slot addresses queue saturation only.
* **Verify before semantic decoding**. For a future v2 config/command format, carry `{v:2, payload_b64, signature_b64}`. Sign the exact decoded payload bytes prefixed by ASCII `trapd-config-v2\n` or `trapd-command-v2\n` respectively. Verify using the pinned key before decoding the typed payload. Include the current signed recipient, replay and action fields in that payload. Route by negotiated version. The existing wire format remains in use.
* **Operational changes**. Configure the final HTTPS backend URL directly. Rotate the mTLS pair together. Bearer-authenticated deployments without a certificate pair retain the existing bootstrap contract. An unreadable signed pin history without another trusted copy blocks connections until provisioned state is repaired. A damaged update watermark blocks new updates until restored from trusted backup. Producers must supply the observed generation on Linux process actions. Privileged installations that previously depended on automatic state-directory fallback need an explicit trusted state path. Linux state and logs require owned directory leaves and trusted, symlink-free ancestors. Restore an existing trusted state directory if the ownership check fails.

## Out of scope findings

Command batch decoding buffers the response before signature validation. Body-size limits belong to the parallel footprint workstream. No fuzz targets or general panic cleanup were added.
