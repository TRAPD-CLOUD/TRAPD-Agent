# Persisted Windows event coverage

The native event-log collector supplements user-mode ETW with operating-system records. It reads Security, System, Application and, when already present, Microsoft-Windows-Sysmon/Operational. `logs_enabled=false` disables these reads. It does not install Sysmon, change audit policy or change registry SACLs.

Security event 4688 supplies the recorded process image, PID, creator PID, command line and account even after the process exits. Administrators must enable **Audit Process Creation (Success)**. Command lines additionally require **Include command line in process creation events**. Missing fields remain unavailable; TRAPD does not substitute a current process with the same PID. Command lines may contain secrets: enabling the Windows policy is an explicit administrator decision.

Security event 4657 supplies registry value create, modify and delete records when **Audit Registry (Success)** and a matching **Set Value auditing SACL** are configured on the target registry key. Without both prerequisites, this is not coverage of transient registry writes. The existing registry snapshot collector remains useful where auditing is absent, but can miss add/remove operations between snapshots.

An existing, administrator-configured Sysmon installation can supply process creation (1), process access (10), registry object create/delete (12), value set (13) and rename (14). Sysmon filters must include the relevant operations and targets. Raw event logs retain process GUIDs, access rights and actor identities. Structured rename records preserve the destination and typed original key/value name; they never treat a target name as observed value data. Watched-object renames produce a low-severity context signal, including movement into or out of a watched scope. Oversized strings/records are bounded with explicit `truncated_fields` byte counts; derived process enrichment also discloses source-field cuts. Structured registry records use the same category table as the snapshot collector and represent unknown previous values as unknown. Key operations use `(Key)` rather than pretending to write a default value. Per-user hive SID identifies the hive owner, not the writer. Both sources can observe the same change; their provenance distinguishes independent observations.

A Sysmon 10 record targeting `lsass.exe` with VM_READ, VM_WRITE or VM_OPERATION rights yields a conservative credential-access **signal**. A query-only handle does not. The signal states observed memory-capable access, not a confirmed credential dump; legitimate diagnostic and security software can produce it. It does not bind historical source PIDs to current processes for destructive response.

User-mode Kernel-Process ETW alone does not capture LSASS handle access. Reading an existing Sysmon channel does not create kernel coverage: Sysmon installs its own driver and its filters, availability, protected-process behavior and event loss determine coverage. TRAPD does not claim complete kernel interception or protection against privileged telemetry tampering.

Online collection waits for the original raw record to be fsynced to the journal before advancing its cursor. Normalized findings can be coalesced independently without stalling the cursor. A journal failure keeps the cursor for retry. Offline NDJSON collection keeps its existing channel handoff semantics.

The registry snapshot baseline is versioned, size bounded and persisted across restarts. Changed values observed while the agent was stopped are compared with the last baseline. Unloaded user hives and unreadable scopes retain their previous values instead of producing false deletion events; newly readable scopes establish a silent baseline. Snapshot tracking retains at most 64 user hives. Loaded, previously tracked hives take priority; excess loaded profiles are visibly excluded while machine monitoring continues. At the user, entry or persisted-byte limits, inactive hive baselines are evicted as complete units, including their availability markers. A reloaded evicted hive establishes a silent baseline: changes made while its baseline was absent cannot be recovered by snapshots. Failed user-root enumeration protects previous baselines from eviction. Online snapshot events must reach the durable journal before the baseline advances. A failed handoff retains one bounded captured poll with stable event IDs; retries skip already confirmed events before scanning again.

Heartbeat `coverage` reports `security_eventlog_active`, `sysmon_eventlog_active`, `audit_process_creation`, `audit_command_line` and `audit_registry` when known. Channel availability is separate from policy and filter coverage. `pipeline.durability_lost` indicates a journal failure and makes health require recovery. These fields do not assert that every target key has an auditing SACL.

Historical process events and raw-record findings retain their original source and timestamp, bypass live PID ancestry/baseline learning, and never authorize automatic response against a currently running process. Signal and shadow findings also cannot trigger automatic response.

The first read of each channel records its newest event without replaying history. Subsequent reads resume a persisted per-channel record cursor. Structured Security logons retain native UTC and provenance and are journaled before their raw-record receipt permits cursor advancement. A pending native record ID prevents re-counting the same login during failed receipt retries. Historical authentication windows use recorded UTC separately from live elapsed time; older out-of-order records remain raw evidence but do not update authentication correlation. Account identities include the domain and username. The collector reads bounded batches (128 records/channel every five seconds); sustained input above this rate can lag and log rollover can lose records. Malformed records are counted and skipped rather than stopping other channels. Missing optional Sysmon is reported once per availability transition. Restart or disabled collection does not guarantee retention beyond Windows log capacity.
